# iCloud安全モード 要件仕様 — 実装延期

> **結論：現在のiCloud Drive上のVaultを移動せず、異常の検知・内容保全・復旧を支援する要件を今定義する。Apple側の同期を停止・修理できるとは約束しない。**

## 1. 位置づけと対象

この文書は、構想v1.0の「iCloudの要件は今、技術方式と実装は後」を満たすための要件基準である。R2をiCloudへ単純置換する仕様ではない。iCloud Remote Backendの実装可能性を確認したわけでもない。

主要利用形態はWindowsとiPhoneで同じiCloud上のノートを使う個人。既存ノート、リンク、添付、設定を消したり、フォルダをR2へ移動したりせず利用できることを目的にする。Obsidian公式はWindowsとのiCloud同期について注意を示している。[同期案内](https://obsidian.md/help/sync-notes)

この文書だけで「iCloudで安全に使える」と宣言しない。実端末API・保管先能力・復旧の試験を、将来のIC-GATEで確認する。

## 2. 利用者の要求

| ID | 利用者の目的 | 必須の結果 |
|---|---|---|
| IC-U01 | 現在の保管場所を変えたくない | Vaultの移動、iCloud無効化、R2契約を要求しない |
| IC-U02 | 重複や急な消失に早く気付きたい | 観測した異常と未確認を分けた通知・一覧 |
| IC-U03 | 消えたり上書きされた内容を取り出したい | 実際に保存した過去版からの非上書き復元 |
| IC-U04 | 難しい操作や毎回の調整を避けたい | 初回確認、診断、復旧の少数の操作へ集約 |
| IC-U05 | ノートや秘密情報を外部へ送られたくない | テレメトリーなし、診断の秘匿化、送信先は明示 |

## 4. 最小UX

初期設定では対象Vaultの場所、他同期との重複、監視対象、設定ファイルを診断対象にするか、過去版保存を使うか、保存先・容量・暗号化の有無を確認する。既定は**読み取り診断のみ**。バックアップ作成や復元は別の明示承認を必要とする。

画面は「診断する」「検出内容を見る」「保存済み版を確認する」「別名で復元する」「診断結果を共有する」を基本とする。各結果に観測時刻・対象端末・未観測/読めない対象を含め、すべての端末で安全な状態と一括断定しない。

大量消失候補は警告するが、自動で削除ファイルを復活させない。Apple側で再度削除が伝播する可能性を説明し、まず独立した保存先へ内容を取り出す。元Vaultへ戻す操作は利用者が状況を確認して別に行う。

## 5. データ保全と機密性

本文は元のUTF-8/バイナリのbytesで保存し、勝手な整形、重複排除による原本削除、プラグイン設定の同期を行わない。backupの索引には版hash、観測元、時刻、bytes、保存状態を記録するが、共有用索引は秘匿化する。

`.obsidian/plugins/*/data.json`等には資格情報が含まれ得るため、設定全体の無条件バックアップや外部共有を既定にしない。設定を含める場合は対象と保管条件を明示する。保存先をクラウドにする方式を後に追加するときは、認証・暗号化・料金の要件を別途設計する。

同じディスク上の過去版は同期事故に対する復旧支援であり、端末故障・盗難に対する独立バックアップではない。存在確認と読み戻しだけで、将来のデータ可用性を保証しない。

## 6. 技術方式を今固定しない部分

iCloud Driveの一般API、CloudKit、Document Picker、File Providerを、普通のObsidian JavaScriptプラグインが任意に使用できると仮定しない。対象Vaultはアプリがアクセスできる範囲でのみ扱う。iCloud上のフォルダをS3 Adapterへ差し込むことも前提にしない。

Windowsで独立したバックアップ先へ書く方式、iPhoneで許可されたアプリ内保存/共有先を使う方式、監視イベントと再走査の組合せは、将来ICLOUD_TECHNICAL_SPECで評価する。必要なネイティブ拡張や追加アプリを、今のMVP0.1の隠れた必須条件にしない。

R2版と共有できる候補は、hash、パス検査、復旧レシートの概念、秘匿化された診断表示。R2のhead CASや共通baselineを、iCloudの同期完了証拠へ流用しない。

## 7. 将来の受入試験

| ID | 試す状態 | 合格条件 |
|---|---|---|
| IC-AT01 | 読み取り診断だけ導入 | 本文/パス/既存設定変更0 |
| IC-AT02 | iCloud上で一部ファイルが未取得/読取失敗 | 削除確定にせず未確認を表示 |
| IC-AT03 | `note.md`と`note 2.md`が同/別内容 | 候補説明のみ、自動削除0 |
| IC-AT04 | 多数の不在観測と不完全走査 | 完全走査だけで候補化、不完全は診断失敗 |
| IC-AT05 | 保存先に空きがない | 保管失敗を通知し元ファイル不変 |
| IC-AT06 | 索引あり/過去版本文なし | 復元可能と表示しない |
| IC-AT07 | 別名復元先が既存 | 非上書きで停止/再選択 |
| IC-AT08 | iPhoneを閉じて再度開く | 未観測期間を示し再走査、常時監視保証なし |
| IC-AT09 | R2モードを同時に有効化 | 拒否し同時書き込みなし |
| IC-AT10 | クラウド同期された端末固有状態 | 他端末の同一性と誤認せず停止/再初期設定 |
| IC-AT11 | ログ/診断の外部共有 | 本文/secret/特定可能なpathを既定で含めない |
| IC-AT12 | 削除伝播中にプラグインを停止 | Apple同期停止とは表示しない。独立復元先を案内 |

すべて未実施。現在の84件とは別の将来要件群であり、MVP0.1の合格件数に加えない。

## 8. 実装へ進む条件

R2版の安全コアと責務を分け、実端末でアクセス能力・保存先・中断・復旧を検証し、iCloud技術仕様をレビューしてから着手する。導入・診断・保存・復元の各副作用に対する利用者承認と、独立バックアップの確認が必要。

未解決なのは技術方式であり、目的や禁止行為は上記のとおり既に定義した。「後で考える」の一行だけにせず、ここを将来実装時の受入契約にする。
